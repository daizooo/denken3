## 3. データ仕様

### 3.1 ID

択一式と同じ規則を流用する（`parseItemId` は選択式を既に扱える）:

| 要素 | 規則 |
|---|---|
| 問ID | `{年度}_S_{RK\|RS}`（例 `R03_S_RK`）。年度は `H29`・`H30`・`R01`〜`R08` |
| 肢ID（空欄） | `{問ID}_{A〜E}`（例 `R03_S_RK_C`）。空欄は書籍の [A]〜[E] |
| 学習科目 | 労基安衛の空欄は、条文が労基法なら `rouki`、安衛法なら `anei`（**空欄ごとに別々**）。労災は `rousai` |
| 出典 → 年度 | 出典 `H30-選択` の年度部分。`R元` → `R01` |

### 3.2 書き起こしJSON（1問=1オブジェクト。作業用）

```json
{
  "question_id": "H30_S_RK",
  "wordbank": { "1": "…", "20": "…" },
  "blanks": { "A": 7, "B": 2, "C": 11, "D": 16, "E": 20 },
  "groups": { "A": [1, 2, 3, 4], "B": [5, 6, 7, 8], "C": [9, 10, 11, 12], "D": [13, 14, 15, 16], "E": [17, 18, 19, 20] },
  "items": [
    { "label": "A", "statement": "…［A］…", "explanation": "（法21条）", "study_subject": "rouki" }
  ],
  "_meta": { "page": 404, "image": "IMG_0217", "difficulty": "普通", "hon_page": "40、121、148、186p", "confidence": "ok" }
}
```

| 項目 | 規則 |
|---|---|
| `wordbank` | 語群①〜⑳を**番号→語句**。語句は書籍のまま（句点・「，」など表記も写す。丸数字は番号に直す）。20語そろうこと |
| `blanks` | 【解答】の空欄 → 語群の番号（5件）。語群の語句と【解答】欄の語句が一致すること。空欄ごとの語群の問は、書籍の「その空欄の①〜④」を**通し番号**（`groups` の番号）に直す |
| `groups` | 空欄ごとに語群が分かれる問だけ。空欄 → その空欄の語群の通し番号の配列（A=1〜4、B=5〜8、…）。5空欄すべてに必要で、正答は自分の空欄の語群の中にあること。既存の公式の `answer_spec.groups`（R08 労災）と同じ形 |
| `items[].statement` | 空欄を含む**段落をそのまま**。空欄は `［A］` の形に統一（既存の公式の取り込みと同じ）。同じ段落に空欄が2つあるときは、両方の肢に同じ段落を入れる（既存の形と同じ）。下の「段落の写し方」に従う |
| `items[].explanation` | 【解答】欄の根拠の括弧書き（条文・判例）をそのまま。**空欄の正答の語句は入れない**（`answer_spec` が持つ） |
| `_meta` | DBに入れない検証用。難易度・必修基本書の参照ページ・信頼度。択一式と同じ扱い |

`truth` は付けない（空欄補充には○×が無い。既存どおり `null`）。`importance` も付けない（§5）。

**段落の写し方**（`statement`）:

- 本文の段落番号（1〜5）は付けない。同じ段落の字下げ改行（判決文の「（1）」「（2）」の区切りなど）は詰めて1つの文字列にする。
- 箇条（一・二・三、イ・ロ・ハ）は、行の記号を残して `\n` で区切る（R03 労災の本文3、R02 労災のイ・ロ）。同じ空欄が複数の箇条にまたがるときは、その箇条を含む段落全体を入れる。
- 書籍の印字を写す。ただし**印刷の乱れ・誤植は写さず**、直した箇所を `_meta.note` に残す: 余分な閉じ括弧（R02 労基安衛の根拠「（則526条1項））」→「（則526条1項）」、R07 労基安衛の「第42条第1項）は」→「第42条第1項は」）、意味の無い記号の混入（R05 労基安衛の「この限りでない」の直後の「0」）。
- 表記は次のとおり統一する: 略記の括弧は**多数派の「〔…（略）…〕」**（書籍に「[…（略）…]」を使う問があるが意味は同じ。括弧に付く空白も入れない）。小書きの「ヵ」（「3ヵ月」）は印字のとおりとし、数字との間の空白は入れない。出典の「R元」は令和元年なので R01。
- 次はそのまま写す: 判決文の旧表記（「であつても」）、全角の英字・数字（「Ｆ紙業」「Ｘさん」「第８条第３項」）。判断に迷うものは `_meta.note` に残し、`confidence` を `check` にする。
- 語群の語句は、書籍が半角カンマ（`1,000人`）なら半角で写す。公式の PDF 由来（`1，000人`）とは全角半角・空白の違いを無視して比べる（§3.3）。

### 3.3 DBへの反映

新規ファイル `scripts/license/ingest-sentaku.mjs`（SQL を出力するだけ。DB には触れない）と、純関数 `sentakuSchema.ts`（検証・公式との突合）・`sentakuSql.ts`（SQL 生成）で行い、`schema.ts` / `ingest.mjs` は触らない。

| 対象 | 既存の行 | 新規の行 |
|---|---|---|
| `lic_questions` | **更新しない**（公式の `stem`・`answer_spec` を守る）。書籍の `blanks`・`wordbank`・`groups` との**一致だけ検証**する（語群の語句は NFKC 正規化して空白を除いて比べる）。食い違いは書き起こしの誤りか公式との差かを確認 | `source='ippon'`・`stem=null`・`answer_spec=` 書籍の `blanks`/`wordbank`（空欄ごとの語群の問は `groups` も。`kind:'sentaku'`） |
| `lic_items` | `statement`・`explanation`・`study_subject` を書籍で更新し、`truth_source='book'` にする（公式の再取り込みが書籍の値を戻さない）。`origin_statement` は上書きしない。`law_status`・`law_note`・`truth` は保持 | `truth_source='book'`・`law_status='ok'`・`truth=null`・`topic_id=null` |

- 本番書き込みは択一式と同じく、承認を得て Supabase MCP の `execute_sql` で行う。ただし DELETE/DROP/TRUNCATE を含む SQL は Claude が実行せず、ユーザーが実行する（全文を PR 本文とチャットに出し、戻し SQL を添える。`licensehub-expansion.md` §4.1）。
- 空欄ごとの語群（`groups`）は、書籍が載せているときは公式の `groups` と同じであること、公式だけが持つときも食い違いとして扱う。R08 労災は書籍の表と公式の `groups` が一致することを確認済み（§8）。

## 4. 品質ゲート

1. **網羅**: 21見開き、20問（10年×2科目）、100空欄。出典の年度が `taiseki_sentaku.json` と一致する。
2. **語群と解答**: 各問で語群が20語、【解答】5件、解答の語句と語群の番号が一致する。空欄ごとの語群の問は、groups が1〜20を過不足なく割り当て、正答が自分の空欄の語群にある。
3. **既存DBとの突合（R06〜R08の6問・30空欄）**: `blanks` と `wordbank` が公式と完全一致すること（一致しなければ書き起こしを画像で再読して原因を特定する。書籍が語群を編集していれば区分として記録する）。`statement` は択一式と同じ区分（①表記 ②単独化 ③内容の変更 ④正誤反転）で分類し、③は1件ずつ確認する。
4. **画像との再照合**: 択一式で差が出たため、**抜き取りではなく全問**を別担当が画像と1文字ずつ照合する（100空欄・語群400語規模で全数が現実的）。
5. **検証の実行**: `ingest-sentaku.mjs --data <json>`（座標・語群・解答・学習科目。DB に触れない）。
6. **法令**: 既存行は判定を保持。新規の行は `ok`。選択式の `review`（R06 国年 B・C など別書籍の科目）は本書の対象外。

## 5. 重要度・論点・索引

- **重要度**: 選択式の空欄は付けない。択一式の出題回数から算出した値（`compute-importance.mjs`）は択一式の肢だけが対象。
- **論点**: 書籍に章分けが無いので `topic_id=null`（論点未設定）。必要になれば、空欄の根拠条文から別途付ける。
- **索引**: `build-master.mjs` は択一式のみ対象（選択式は含めない）。このため現状、選択式は復習・一覧のリストに出ない（問ID `R03_S_RK` から `answer_spec` を読む画面経路はあるが、入口が無い）。一覧に出して絞り込めるようにするには索引への追加が要り、復習キュー・進捗・合格ライン母数に影響するため、別途判断する。

## 7. 実装の記録（基盤）

### 取り込みの手順（Claude Code が実行）

1. `ingest-sentaku.mjs --data <json> --check-sql <path>` で検証し、突合用 SQL を作る。
2. 突合用 SQL を `execute_sql` で実行し、結果（`[{id, answer_spec}, …]`）を JSON にして `--existing <json>` で突合する。食い違えば理由つきで一覧にして終了コード 1（保存用 SQL は作らない）。
3. `--sql <path>` で保存用 SQL を作り、承認を得て `execute_sql` で実行する。実行した SQL の全文と件数を PR 本文に報告する。

### 保存の規則

- `lic_questions` は新規の問だけ作る（`ON CONFLICT DO NOTHING`）。既存の問の `answer_spec` が書籍と違えば、保存用 SQL 自体が例外で中止する（何も書かない）。
- `lic_items` は `statement`・`explanation`・`explanation_source`・`explanation_verified`・`study_subject`・`truth_source`（`'book'`）の6列だけ上書きする。`origin_statement`・`truth`・`law_status`・`law_note` は据え置く。
- 書籍で上書きした空欄は `truth_source='book'` になるため、公式PDFの再取り込み（`ingest-official.mjs`。`merge.ts` の `keepIfBook`）を同じ年度で再実行しても `statement`・`study_subject` は戻らない（公式の原文は `origin_statement` に入る）。`truth` は空欄補充では `null` のままで、突合の食い違いにも数えない。
- 20問そろっていなければ `--partial` が必要。語群の `groups`（R08 の空欄ごとの語群）は突合の対象にしない（§3.3）。

### 動作確認（クラウド環境）

使い捨ての Postgres 16 に最小のテーブルを作り、保存用 SQL を2回流して、新規の問・空欄が入ること、既存の空欄の `origin_statement`・`law_status`・`law_note` が残ること、公式PDFの取り込み SQL を後から流しても書籍の本文が戻らないこと、再実行で結果が変わらないこと、既存の `answer_spec` を食い違わせると何も保存せず中止することを確認した。

- 実データでの動作確認（§8）: 公式の既存6問・30空欄を入れた一時 Postgres に、書籍の20問・100空欄の保存用 SQL を流した。新規14問・既存6問、空欄100件（既存30件は `origin_statement` が残り、`truth_source='book'`）。2回流しても同じ。既存の正答・語群・groups を食い違わせると中止する。
