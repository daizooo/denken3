# 分野別取り込み「認識されない」の実データ検証（GoogleDrive 接続）

検証日: 2026-08-31 23:35 JST / 対象: 電子理論(`etheory`)・電子回路(`ecircuit`)・電気計測(`meas`)

`docs/etheory-ecircuit-import-investigation.md`（PR #105）で特定した原因に対する修正が、
**現行の GoogleDrive の実ファイル名で本当に成立するか**を、Drive・Storage・DB の現物に
当たって確認した記録。コード変更は伴わない。

## 1. 結論

- 修正（PR #105・`c92e683`）は**現行 Drive の実ファイル名で正しく動く**。3章とも
  マッピングの全キーへ過不足なく到達し、解決されないのは捨て問だけだった（§3）。
- 「認識されない」状態で操作していた時点の本番はまだ**修正前のビルド**だった。
  修正が本番へ出たのは **2026-08-31 23:19 JST**（`091fc4d` の production デプロイ）で、
  それ以前に開いた画面は完全一致のみの旧コードのままである。
  本番を読み込み直した上で再実行すれば取り込める。
- 画像は**まだ1枚も入っていない**（Storage に `etheory`/`ecircuit` のフォルダ自体が無い）。
  「アップロードは済んだが認識だけされていない」ではなく、アップロード段階に達していない。
- 未取り込みは **⑧電子理論・⑨電子回路の2章だけ**。⑦電気計測（`meas`）は取り込み済みのため、
  参考として同じ検証を通し、現行 Drive の名前でも再取り込みできることを確認した（§4）。

## 4. 章の対象範囲

分野別（理論）の章は ①直流回路 ②単相交流 ③三相交流 ④過渡現象 ⑤静電気 ⑥電磁気
⑦電気計測 ⑧電子理論 ⑨電子回路 の9つ。

- 未取り込みは **⑧電子理論・⑨電子回路**の2章のみ。今回の対象はこの2章。
- ⑦電気計測（`meas`）は取り込み済み（Storage 50枚 / DB 51行）で、再取り込みの必要はない。
  名前が紛らわしい章が隣接するため、取り違えて渡していないかの確認用に §3 へ併記した。

## 5. この環境からサーバ側で投入できない理由

本セッションの `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` は **denken3 ではない別プロジェクト**を
指しているため、ここから Storage へ画像を投入することはできない（同じ事象は PR #106 の
`eccf814` でも確認され、スクリプト側は1枚も上げずに止まるようになっている）。
投入は、本人セッションのブラウザから取り込みパネルで行うか、denken3 の認証情報を
`.env` に入れた手元の環境からバッチで行う必要がある。

## 6. 取り込み手順（本番再読込後）

1. 本番（`denken3-six.vercel.app`）を**再読み込み**する。ホーム画面から起動している場合は
   一度アプリを終了してから開き直す（23:19 JST より前に開いた画面は旧ビルドのまま）。
2. 取り込みパネル →「分野別」→ 章で **電子理論** を選ぶ（⬜ 表示・想定46枚）。
3. ⑧電子理論フォルダの50枚を選択・ドラッグする → 46枚が登録、捨て問4枚はスキップ。
4. 同様に **電子回路** を選び、⑨電子回路フォルダの81枚を渡す → 69枚が登録。
5. 完了後、章の表示が ✅（46枚 / 69枚）になる。0件で終わる場合は、パネルに出る
   「渡されたファイル名の例」と選択中の章名を確認する。

なお iPhone / iPad で写真アプリ経由の画像を選ぶと元のファイル名が失われることがある。
Drive からは「ファイル」アプリへ保存し、ファイル選択から渡すこと（`問N.png` の名前が
残っていることが解決の前提）。

## 7. 残るリスク（未対処）

`問N` は章ローカルな命名なので、**章を取り違えたまま渡すと、番号が重なる範囲では
別章の画像が解決されてしまう**（例: 電子理論を選んだまま ⑨電子回路の `問1.png` を渡すと
`etheory_1` として登録される）。修正前は「完全一致しない＝全件スキップ」だったため
起こらなかった経路であり、取り込み枚数が想定と食い違ったときは章の選択を疑うこと。
