# 電子理論・電子回路の取り込みが完了していなかった原因と修正

調査日: 2026-08-31 / 対象: `etheory`（電子理論）・`ecircuit`（電子回路）

## 1. 結論（根本原因）

**分野別取り込みが「ファイル名の完全一致」でしか問題を引けないまま放置されていたこと。**

同じ不具合は年度別取り込みで一度発生し、**PR #56（`02f3b2b` / 2026-07-25）で修正済み**である。

> 年度別取り込み: ファイル名の「問N」表記からも問題を逆引き
> GoogleDriveからそのまま持ってきた電験王キャプチャの元ファイル名は imageFile と
> 完全一致しないため**全件スキップされていた**。

このとき修正されたのは `handlePaperFiles`（年度別）だけで、`handleFiles`（分野別）は
`ASSET_MAP[f.name]` の完全一致のままだった。つまり **「取り込み元のファイル名は変わりうる」
という既知の前提に対して、2つある取り込み経路の片方しか対応していなかった**。

電子理論・電子回路は、その未修正の経路を最初に踏んだ章である。

### なぜこの2章だけなのか

章は番号順（①直流回路 → ⑨電子回路）に取り込まれており、**⑦電気計測まで終わった時点で
取り込み元のファイル名が変わった**。時系列は以下のとおり。

| 日時 | 出来事 |
|---|---|
| 2026-07-21 | ①直流回路を取り込み（`newIMG_0283`〜） |
| 2026-07-22 | ②単相交流・④過渡現象・③三相交流・⑤静電気・⑥電磁気を取り込み |
| 2026-07-24 08:00 / 23:38 | ⑦電気計測を取り込み（`newIMG_0478`〜`0537`）＝**旧命名での最後の取り込み** |
| 2026-07-25 00:31 | PR #56。年度別の「完全一致で全件スキップ」を修正（**分野別は未修正のまま**） |
| 2026-08-03 07:52 | GoogleDrive の章フォルダ一式が `問N.png` 形式で作り直される |
| それ以降 | ⑧電子理論・⑨電子回路を取り込もうとしても、分野別は完全一致のみなので1件もヒットしない |

①〜⑦は「命名が変わる前に取り込みが済んでいた」から無事だっただけで、
**この2章に固有の欠陥があったわけではない**。同じ理由で、既存7章の再取り込みも
現行の Drive ファイルからは不可能な状態だった（Storage 上の既存357枚は旧名で
保存済みのため、閲覧自体には影響しない）。

### なぜ失敗に気づけなかったのか

一致0件のとき、分野別ハンドラは例外もエラーも出さずこう表示して終了していた。

```
対象の画像が見つかりませんでした（50件は未登録/捨て問のためスキップ）。
```

「捨て問だからスキップ」という**正常系に読める文面**であり、かつ取り込み済みかどうかを
確認する手段がパネル上に無かった（年度別には ✅/⬜ の一覧があるが、分野別には無かった）。
失敗が失敗として見えないことが、放置が続いた第2の原因である。

## 2. 事実確認

### 2.1 DB（`denken_question_assets`）

`etheory` / `ecircuit` の行は **0 件**。他の理論7章はすべて登録済み。

| chapter | rows | questions | files |
|---|---|---|---|
| dc | 71 | 69 | 70 |
| ac1 | 70 | 69 | 68 |
| trans | 16 | 14 | 15 |
| ac3 | 26 | 22 | 26 |
| elec | 78 | 72 | 74 |
| mag | 56 | 55 | 54 |
| meas | 51 | 45 | 50 |
| **etheory** | **0** | **0** | **0** |
| **ecircuit** | **0** | **0** | **0** |

### 2.2 Storage（`denken-problems`）

`{uid}/theory/` 配下の実ファイルは **357枚**（dc 70 / ac1 68 / trans 15 / ac3 26 /
elec 74 / mag 54 / meas 50）で過不足なく、`etheory` / `ecircuit` のフォルダ自体が無い。
**アップロード段階にすら到達していない**（DB登録だけ失敗したのではない）。

### 2.3 GoogleDrive 側のファイル名

親フォルダ配下の章フォルダ（⓪電気の基本〜⑨電子回路）は**全章とも `問N.png` 形式**。
`newIMG` で Drive 全体を検索してヒット **0件**（旧命名のファイルは1つも残っていない）。

- ⑧電子理論: `問1.png`〜`問46.png`、またがりは `問13-1.png` / `問13-2.png`（計50枚）
- ⑨電子回路: `問1.png`〜`問58.png`、またがりは `問9-1.png` / `問9-2.png`（計81枚）
- ⑦電気計測: `問1.png`〜`問51.png`（`問31,32.png` = 2問同居）

同一コーパスの改名であることは枚数で裏が取れる。例えば電気計測は Drive 実枚数59枚で、
`docs/problem-data-integration.md` の「59枚実読」と一致する。

### 2.4 マッピング定義自体は正しい

| | MASTER 登録 | 捨て問 | またがり | `*Assets.ts` の行数 | Drive 実枚数 |
|---|---|---|---|---|---|
| etheory | 42（問1〜46） | 4（問5,9,20,45） | 4（問13,35,40,46） | 46 = 42+4 | 50 = 46+4 |
| ecircuit | 52（問1〜58） | 6（問13,14,15,41,46,54） | 17 | 69 = 52+17 | 81（+奥付1は Drive に無し） |

`問N` の N は MASTER の `number` と一致し、`-1` / `-2` は `sort` 0/1 に対応する。
**マッピングを作り直す必要はなく、引き方だけが古かった。**

## 3. 修正内容

年度別（PR #56）と同じ考え方を分野別へ適用した。

### 3.1 `src/lib/bunyaFilename.ts`（新規）

章スコープでファイル名を解決する `resolveBunyaFile(chapter, filename)` を追加。

| 入力 | 解決先 |
|---|---|
| `newIMG_0550.png` | 完全一致（既存7章の再取り込み互換） |
| `問13.png` / `問13-1.png` | その章の問13・`sort 0` の正規ファイル名 |
| `問13-2.png` | 問13の解答続きページ・`sort 1` |
| `問31,32.png` | 2問同居画像（先頭番号で解決） |
| 捨て問・奥付・章違い・想定外 | `undefined`（従来どおりスキップ） |

`問N` は章ローカルで章をまたぐと一意でない（`問1.png` は9章すべてに存在する）ため、
必ず章コードとセットで引く。

### 3.2 `src/lib/assets.ts`

`ASSET_MAP` を章コード別の `CHAPTER_ASSET_MAPS` から組み立てる形に変更（統合マップの
中身は従来と同一。`hasKnownAsset` などの既存利用に影響なし）。

### 3.3 `src/components/ImportPanel.tsx`

- 分野別モードに**章の選択**を追加（年度別の回選択と同じ形）。各章に ✅/⬜ と
  保存枚数・想定枚数を表示し、**未取り込みの章がパネル上で分かる**ようにした。
- 保存先ファイル名を `ASSET_MAP` 上の正規名へ統一（年度別が `imageFile` へ統一するのと同じ）。
  元ファイル名が `問13.png` でも Storage には `newIMG_0550.png` として入るため、
  既存7章と同じ規約のまま混在しない。
- 一致0件のときのメッセージを、正常系に読めない診断的な内容へ変更した。

```
✗ 電子理論 に紐付く画像が1件もありませんでした（50件すべてスキップ）。
想定するファイル名: 「問13.png」「問13-2.png」または「newIMG_0550.png」
渡されたファイル名の例: 問1.png / 問2.png / 問3.png
選択中の章が、取り込もうとしているフォルダと一致しているか確認してください。
```

## 4. 検証

現行 GoogleDrive の実ファイル名一覧を入力に、解決結果を突き合わせた（`npm run build` も通過）。

```
1) 完全一致(既存互換): 全9章 472 件 OK
2) etheory: Drive実ファイル 50枚 -> 解決 46件 / マッピング 46件 完全一致 OK
2) ecircuit: Drive実ファイル 81枚 -> 解決 69件 / マッピング 69件 完全一致 OK
3) 2問同居: 問31,32.png と 問32.png がともに newIMG_0511.png（2問）へ解決 OK
4) 章違い・範囲外・未知命名は解決しない OK
```

- 既存7章の正規名472件はすべて従来どおり完全一致で解決される（後方互換）。
- 電子理論50枚・電子回路81枚は、捨て問（それぞれ4枚・12枚）を除いた全枚数が
  マッピングの全キーと**過不足なく1対1で対応**する。
- 他章の正規名・存在しない番号・無関係な命名は解決されない（取り違え防止）。

## 5. 残作業

コード側の経路は通ったが、**画像の実投入は利用者の操作が必要**（取り込みはログイン中の
本人セッションでブラウザから非公開ストレージへ直接アップロードする設計のため）。

1. 取り込みパネル →「分野別」→ 章で「電子理論」を選ぶ
2. ⑧電子理論フォルダの50枚をドラッグ（46枚が登録され、捨て問4枚はスキップされる）
3. 同様に「電子回路」を選び、⑨電子回路フォルダの81枚をドラッグ（69枚が登録）

完了後は章の表示が ✅（46枚 / 69枚）になる。
`docs/problem-data-integration.md` §5.1 の状態欄も「投入済み」へ更新すること。
