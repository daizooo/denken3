## 1. 目的と前提

LicenseHub の3つ目の資格として「2級建設業経理士」を追加する。**他資格（社労士・1級土木）とは混ぜない**
（`exam_id='kenkei2'`・ID接頭辞 `K2_`・専用テーブル。社労士の `lic_*`、土木の `dbk_*` には一切書かない）。

| 前提 | 内容 |
|---|---|
| 利用環境 | **会社の PC だけ**。紙・電卓アプリ以外の手書きは使えない → 解答は画面で完結させる（§4） |
| 出典 | 利用者の Google ドライブ「2級建設業経理士」：問題PDF 6本（第34〜39回）＋ 解答PDF 6本（資格スクール大栄の模範解答） |
| 開発環境 | クラウドのみ（`CLAUDE.md`）。取り込みは Drive → この環境 → DB（本文はリポジトリに置かない） |

## 2. 試験の構造（6回分の PDF を画像で確認した結果）

6回とも同じ形で、100点満点（配点は大栄の予想。公式の配点ではない）。

| 大問 | 内容 | 配点 | 解答の形 |
|---|---|---|---|
| 第1問 | 仕訳5問（勘定科目群 A〜X から記号と科目、金額） | 20（1組4点） | 借方・貸方とも複数行あり |
| 第2問 | 空欄の金額4問（年数が答えの回あり） | 12（各3点） | 数値 |
| 第3問・第4問 | 原価計算・工事原価。回ごとに種類が変わる（下表）。**第36回だけ第3問と第4問の内容が入れ替わる** | 14 と 24 | 数値・記号・表 |
| 第5問 | 決算整理事項→**精算表**（約45行×8列）。10項目前後の整理事項 | 30（網掛け15マス×2点） | 表のマス |

第3・第4問に出る形（全6回で確認）:

| 形 | 例 | 採点単位 |
|---|---|---|
| 金額の問（A〜D の金額、予定配賦率・配賦額、配賦差異と有利/不利の記号） | 材料元帳（先入先出法・移動平均法・総平均法）、予定配賦 | 1問=2〜5点。差異は「金額＋記号」の両方正解で得点 |
| 記号選択（A〜L の用語、A/B の算入可否） | 実際原価計算の段階、工事原価に算入するか | 1つ=1〜2点 |
| T勘定・報告書 | 未成工事支出金・完成工事原価・損益・**完成工事原価報告書** | 1マス=2点 |
| 配賦表 | **部門費振替表**（直接配賦法）、**工事別原価計算表**、工事原価明細表 | 網掛けのマス=2点 |

- 解答PDFは網掛けのマスが採点対象。精算表は 15マス（第36・39回で網掛けを確認）。**採点対象のマスは PDF の網掛け矩形から機械的に取れる**。
- 問題PDFは4ページで**解答用紙を含まない**。表の枠（行・列・与件の数値）は解答PDFから復元する。
- 合格基準は70点以上・試験時間90分と理解しているが**未確認**（公式で確認して `src/data/kenkei2/index.ts` の設定値1か所に置く）。

## 3. 取り込みの方針

### 3.1 出典ごとの扱い

| 素材 | 扱い | 理由 |
|---|---|---|
| 問題PDF（4ページ） | 第1・2問は**文字起こし**、第3〜5問の資料（元帳・配賦表・整理事項）は**原本ページから切り出した画像** | 文字抽出は数字・記号の字形が壊れる（`&#2;` などに化ける。1級土木と同じ症状）。表を手で書き起こすより画像のほうが誤写が無い |
| 解答PDF（模範解答） | **正答の金額・科目・記号・網掛け位置だけ**を構造化データにする | 6本ともテキストが読める。数値は整合チェックで検証できる（§3.3） |
| 解答PDFの解説・配点 | 解説は**転記しない**（大栄の著作物）。配点は「予想」と明記して持つ | 解説は別途 AI 解説（根拠付き・未確認フラグ）を作る場合のみ |

保存は DB のみ。リポジトリに置くのは設計書・スクリプト・テスト・索引（ID と短い論点名）だけ（社労士 §4.1・土木 §6.5 と同じ）。

### 3.2 カードの単位（FSRS）

1設問 = 1カード。1回あたり約13〜15枚、6回で約85枚。

| 種別 | カード | 例（ID） |
|---|---|---|
| 仕訳 | 1組 | `K2_39_1_1` 〜 `K2_39_1_5` |
| 空欄金額 | 1問 | `K2_39_2_1` 〜 `K2_39_2_4` |
| 第3問・第4問 | 設問（問1・問2…）単位 | `K2_39_3_1`、`K2_39_4_2` |
| 精算表 | 1表まるごと | `K2_39_5_1` |

ID は `K2_{回2桁}_{大問}_{設問}`。既存 ID（`D1_…`・社労士）と衝突しない。

### 3.3 取り込みの検証ゲート（通らなければ保存しない）

- 仕訳: 借方合計 = 貸方合計。勘定科目の記号が科目群に実在する。
- 精算表: 各列の合計が最終行と一致（試算表・整理記入・損益計算書・貸借対照表の貸借）。当期純利益が PL と BS で一致。
- 配点: 回ごとの合計が100点。採点マスの数 × 点 = 大問の配点。
- 件数: 回ごとの設問数（仕訳5・空欄4 ほか）が揃っている。
- 数値の取り違え対策: 抽出結果をページ画像と目視で突合（1回あたり精算表と部門費振替表を重点）。

## 4. 解き方（会社のPCだけで完結する）

紙が使えないため、**全設問を画面に入力して自動採点**する（1級土木の「選ぶだけ」とは別物。ここがこの資格の最大の違い）。

### 4.1 入力部品（5種で全設問を覆う）

| 部品 | 使う設問 | 入力の工夫 |
|---|---|---|
| 仕訳 | 第1問 | 借方・貸方の行を追加/削除。科目は**記号キー（A〜X）または科目名の前方一致**で選べる。金額は数字のみ |
| 金額 | 第2問・第3問・第4問 | 半角・全角・カンマ付きを許容して正規化。単位は「円」固定 |
| 記号選択 | 第3・4問 | 選択肢（A〜L）をボタン／キー入力 |
| 表 | 部門費振替表・工事別原価計算表・T勘定・原価報告書 | **採点マスだけが入力欄**。それ以外は印字済みとして表示 |
| 精算表 | 第5問 | 採点マス15個が入力欄。行は固定。Tab/Enter で次の入力欄へ。整理仕訳の計算用に**メモ欄**（下書きは自動保存） |

- 問題は画面の左（または上）に表示し、解答欄は同じ画面の右（または下）に置く。スクロールで問題と解答欄を往復させない。
- 計算の途中（紙の代わり）は画面のメモ欄に書く。電卓は OS のものを使う前提で、画面には作らない。
- 精算表は解くのに長時間かかるため、**途中保存**（ブラウザの下書き。送信は採点時だけ）を必須とする。

### 4.2 採点と記録

- 採点は**採点マス（網掛け）の完全一致**。部分点は配点どおり（予想配点）。金額と記号が対の設問は両方正解で得点。
- 仕訳は借方・貸方それぞれの行の順序を問わない。同じ科目で複数行に分けた入力は、科目ごとに合算して比較する。
- 結果の写像（案）: 満点かつ確信あり=A、満点で迷い=B、満点未満=C。**精算表は満点が厳しすぎるため、得点率 80%以上を正解扱い**とする（要調整）。
- 記録は既存の `denken_reviews`（`exam_id='kenkei2'`）。FSRS・保持率ポリシー・送信待ち・取り消しは1級土木（`src/lib/doboku1/record.ts`）と同じ純関数を再利用する。
- 誤答のマスは正答と並べて表示（行ごとに ○/×）。解説は付けない（§3.1）。

## 5. データモデル（追加のみ）

新規テーブル（migration は**実装完了・コミット直前に採番**。現時点の最新は 036。`CLAUDE.md` §4）。

```
denken3.kk2_questions
  user_id, id ('K2_39_1_1'), exam_no (34..39), part (1..5), sub (1..)
  form_kind    ('journal' | 'amount' | 'symbol' | 'table' | 'settlement')
  topic        短い論点名（例: 剰余金の配当、完成工事高（進行基準））
  points       配点（予想）
  stem         問題文（第1・2問は文字、第3〜5問は空）
  stem_images  問題ページの切り出し画像（data URI の配列。第3〜5問）
  frame        解答欄の定義（JSONB。科目群・行・列・採点マスの座標）
  key          正答（JSONB。frame の採点マスと同じキー）
  updated_at
RLS: 本人のみ（dbk_questions と同形）。GRANT: authenticated・service_role のみ（anon なし）。
```

- `frame` と `key` は TypeScript の型（`src/lib/kenkei2/types.ts`）と検証関数（`src/lib/kenkei2/validate.ts`）で定義し、取り込みと画面の両方が使う。
- 画像は 130dpi・JPEG に縮小（1枚 100〜200KB）。回あたり3〜4枚。DB 容量は6回で数MBの見込み。

## 8. リスク

| リスク | 対策 |
|---|---|
| 配点は大栄の予想で公式と異なる | 画面に「配点は予想」と表示。合否の断定表示はしない |
| 解答PDFの誤りや、公式と異なる解答 | 検証ゲート（§3.3）で整合しないものは保存しない。回ごとに公式の解答と照合できる余地を残す |
| 精算表のマス数が多く入力が重い | 採点マスだけを入力欄にする（15マス）。キー操作で移動。途中保存 |
| 表記の揺れ（全角/半角・カンマ・「¥」） | 正規化関数でそろえる（K1 でテスト） |
| 問題・解答の転載の権利 | 本文・画像・正答は DB のみ（本人のみ RLS）。解説は転記しない |
| 社労士・土木への影響 | 新規テーブル・新規接頭辞・`AnyItemSolver` の1行のみ。既存の集計は `exam_id` で分離済み |

## 9. 決めたこと（異論があればここを直す）

1. 解答は**全設問を画面入力＋自動採点**。紙・手書きは前提にしない。
2. 第1・2問は文字、第3〜5問の資料は画像で取り込む。
3. 解説は転記しない（正答のみ）。
4. FSRS のカードは設問単位（約85枚）。精算表は1カード。
5. 取り込みの順序は第39回（最新）→ 第38〜34回。
