## 1. 目的と前提

（`exam_id='kenkei2'`・ID接頭辞 `K2_`・専用テーブル。社労士の `lic_*`、土木の `dbk_*` には一切書かない）。

| 前提 | 内容 |

| 利用環境 | **会社の PC だけ**。紙・電卓アプリ以外の手書きは使えない → 解答は画面で完結させる（§4） |
| 出典 | 利用者の Google ドライブ「2級建設業経理士」：問題PDF 6本（第34〜39回）＋ 解答PDF 6本（資格スクール大栄の模範解答） |

## 2. 試験の構造（6回分の PDF を画像で確認した結果）

6回とも同じ形で、100点満点（配点は大栄の予想。公式の配点ではない）。

| 大問 | 内容 | 配点 | 解答の形 |
|---|---|---|---|
| 第1問 | 仕訳5問（勘定科目群 A〜X から記号と科目、金額） | 20（1組4点） | 借方・貸方とも複数行あり |
| 第2問 | 空欄の金額4問（年数が答えの回あり） | 12（各3点） | 数値 |
| 第3問・第4問 | 原価計算・工事原価。回ごとに種類が変わる（下表）。**第36回だけ第3問と第4問の内容が入れ替わる** | 14 と 24 | 数値・記号・表 |
| 第5問 | 決算整理事項→**精算表**（約45行×8列）。10項目前後の整理事項 | 30（網掛け15マス×2点） | 表のマス |

第3・第4問に出る形（全6回で確認）:

| 形 | 例 | 採点単位 |
|---|---|---|
| 金額の問（A〜D の金額、予定配賦率・配賦額、配賦差異と有利/不利の記号） | 材料元帳（先入先出法・移動平均法・総平均法）、予定配賦 | 1問=2〜5点。差異は「金額＋記号」の両方正解で得点 |
| 記号選択（A〜L の用語、A/B の算入可否） | 実際原価計算の段階、工事原価に算入するか | 1つ=1〜2点 |
| T勘定・報告書 | 未成工事支出金・完成工事原価・損益・**完成工事原価報告書** | 1マス=2点 |
| 配賦表 | **部門費振替表**（直接配賦法）、**工事別原価計算表**、工事原価明細表 | 網掛けのマス=2点 |

- 解答PDFは網掛けのマスが採点対象。精算表は 15マス（第36・39回で網掛けを確認）。**採点対象のマスは PDF の網掛け矩形から機械的に取れる**。
- 問題PDFは4ページで**解答用紙を含まない**。表の枠（行・列・与件の数値）は解答PDFから復元する。
- 合格基準は70点以上・試験時間90分と理解しているが**未確認**（公式で確認して `src/data/kenkei2/index.ts` の設定値1か所に置く）。

## 3. 取り込みの方針

### 3.1 出典ごとの扱い

| 素材 | 扱い | 理由 |
|---|---|---|
| 問題PDF（4ページ） | **文字**で取り込む（全大問）。表は列の区切りをタブで残す | 数字・記号の字形が ToUnicode を持たず制御文字に化けるが、フォントの `/Differences`（字形名 `c2690〜c2699` = 0〜9 など）から復元できた（`extract_problems.py`）。画像は DB への投入が現実的でない（投入は SQL を私の入出力に通す方式しかなく、base64 は数MBになる）うえ、文字のほうが画面で読みやすい |
| 解答PDF（模範解答） | **正答の金額・科目・記号・網掛け位置だけ**を構造化データにする | 6本ともテキストが読める。数値は整合チェックで検証できる（§3.3） |
| 解答PDFの解説・配点 | 解説は**転記しない**（大栄の著作物）。配点は「予想」と明記して持つ | 解説は別途 AI 解説（根拠付き・未確認フラグ）を作る場合のみ |

保存は DB のみ。リポジトリに置くのは設計書・スクリプト・テスト・索引（ID と短い論点名）だけ（社労士 §4.1・土木 §6.5 と同じ）。

### 3.2 カードの単位（FSRS）

1回あたり12枚、6回で72枚。第3〜5問は大問ごとに1枚（設問ごとに分けると、表や資料を共有する問を切り分ける手間と誤りが増えるため）。

| 種別 | カード | 例（ID） | 配点 |
|---|---|---|---|
| 仕訳 | 1組 | `K2_39_1_1` 〜 `K2_39_1_5` | 4 |
| 空欄金額 | 1問 | `K2_39_2_1` 〜 `K2_39_2_4` | 3 |
| 第3問・第4問 | 大問 | `K2_39_3_1`、`K2_39_4_1` | 14・24（第36回のみ逆） |
| 精算表 | 1表まるごと | `K2_39_5_1` | 30 |

ID は `K2_{回2桁}_{大問}_{設問}`。既存 ID（`D1_…`・社労士）と衝突しない。第3〜5問は満点が厳しいため、得点率 80%以上を「正解」とする（§4.2）。

### 3.3 取り込みの検証ゲート（通らなければ保存しない）

- 仕訳: 借方合計 = 貸方合計。勘定科目の記号が科目群に実在する。
- 精算表: 各列の合計が最終行と一致（試算表・整理記入・損益計算書・貸借対照表の貸借）。当期純利益が PL と BS で一致。
- 配点: 回ごとの合計が100点。採点マスの数 × 点 = 大問の配点。
- 件数: 回ごとの設問数（仕訳5・空欄4 ほか）が揃っている。
- 数値の取り違え対策: 抽出結果をページ画像と目視で突合（1回あたり精算表と部門費振替表を重点）。
- 仕訳の記号と科目名: 解答の記号→科目名が、**問題PDFの勘定科目群と一致**すること（独立した2つのPDFの突き合わせ。第34〜39回の30組で不一致0）。
- 問題文: 空でなく、復元できない字形が残っていないこと。回ごとの配点合計が 100。
- **DB への投入後の照合**: 投入は SQL を私の入出力に通すため、転記の取り違えが起こりうる（実際に第39回の罫線1要素で1回起きた）。投入後に `md5(stem)`・`md5(frame::text)`・`md5(key::text)` を DB で計算し、`scripts/kenkei2/hashes.py`（jsonb::text と同じ表記で計算）と全行を突き合わせる。不一致があれば要素ごとのハッシュで箇所を特定して直す。

## 4. 解き方（会社のPCだけで完結する）

紙が使えないため、**全設問を画面に入力して自動採点**する（1級土木の「選ぶだけ」とは別物。ここがこの資格の最大の違い）。

### 4.1 入力部品（4種で全設問を覆う。`src/features/kenkei2/`）

| 部品 | 使う設問 | 入力の工夫 |
|---|---|---|
| 仕訳（`JournalForm`） | 第1問 | 借方・貸方の行を追加/削除。科目は**記号（A〜Y）**で入れると科目名が出る（本番どおり記号と科目を答える）。全角・小文字・カンマ可。勘定科目群を上に表示 |
| 金額 | 第2問 | 全角・カンマ・¥付きを許容。単位（円・年）は固定 |
| 解答用紙の複製（`SheetForm`） | 第3・4問 | 解答PDFの文字・罫線を座標どおり写し、**採点対象の欄だけを入力欄**にする（金額・記号・複数欄の組）。採点前は、採点対象外の途中の数値（`frame.hide`。部門費振替表）を隠す |
| 精算表（`SettlementForm`） | 第5問 | 試算表は印字。**採点対象の15欄だけが入力欄**。整理記入などの計算は**メモ欄**。採点後に模範解答の精算表（全欄）を表示 |

- **Enter で次の入力欄へ**（日本語入力の確定の Enter は除く）。PC のキーボードだけで表を埋められる。
- **下書きは自動保存**（localStorage。記録したら消す。サーバーには送らない）。解き直しの途中で閉じても失わない。
- 問題文と解答欄は同じ画面に縦に並べる（解答欄を問題文の直下に置き、メモ欄は最下部）。
- 採点後は、誤りの欄に「正: …」を表示。仕訳は借方・貸方ごとに○×と正答を表示。

### 4.2 採点と記録

- 採点は**採点マス（網掛け）の完全一致**。部分点は配点どおり（予想配点）。金額と記号が対の設問は両方正解で得点。
- 仕訳は借方・貸方それぞれの行の順序を問わない。同じ科目で複数行に分けた入力は、科目ごとに合算して比較する。
- 結果の写像（案）: 満点かつ確信あり=A、満点で迷い=B、満点未満=C。**精算表は満点が厳しすぎるため、得点率 80%以上を正解扱い**とする（要調整）。
- 記録は既存の `denken_reviews`（`exam_id='kenkei2'`）。FSRS・保持率ポリシー・送信待ち・取り消しは1級土木（`src/lib/doboku1/record.ts`）と同じ純関数を再利用する。
- 誤答のマスは正答と並べて表示（行ごとに ○/×）。解説は付けない（§3.1）。

## 5. データモデル（追加のみ）

新規テーブル（migration は**実装完了・コミット直前に採番**。現時点の最新は 036。`CLAUDE.md` §4）。

```
denken3.kk2_questions   （migration 037）
  user_id, id ('K2_39_1_1'), exam_no (34..39), part (1..5), sub (1..)
  form_kind  ('journal' | 'amount' | 'sheet' | 'settlement')
  points     配点（予想）
  stem       問題文（第3〜5問は表の列の区切りをタブで残す）
  frame      解答欄の定義: 仕訳=科目群 / 金額=単位 / 第3・4問=解答用紙の複製（words・rules）と採点単位（units） / 精算表=勘定科目と試算表
  key        正答（採点単位・採点マスと同じキー）
RLS: 本人のみ（dbk_questions と同形）。GRANT: authenticated・service_role のみ（anon なし）。
```

- `frame` と `key` は TypeScript の型（`src/lib/kenkei2/types.ts`）と検証関数（`src/lib/kenkei2/validate.ts`）で定義し、取り込みと画面の両方が使う。
- 1回あたり 21〜45KB（第39回は 25KB）。6回で約 190KB。画像は使わない（§3.1）。
- 第3・4問の `frame.words` には、模範解答で網掛けでない数値（採点対象外のセル）も含まれる。本番の解答用紙では空欄だった可能性があり、そのまま見せるとヒントになる。表示の扱い（隠す・表示する）は K4 で決める（データは DB に正確に残してある）。

## 8. リスク

| リスク | 対策 |
|---|---|
| 配点は大栄の予想で公式と異なる | 画面に「配点は予想」と表示。合否の断定表示はしない |
| 解答PDFの誤りや、公式と異なる解答 | 検証ゲート（§3.3）で整合しないものは保存しない。回ごとに公式の解答と照合できる余地を残す |
| 精算表のマス数が多く入力が重い | 採点マスだけを入力欄にする（15マス）。キー操作で移動。途中保存 |
| 表記の揺れ（全角/半角・カンマ・「¥」） | 正規化関数でそろえる（K1 でテスト） |
| 問題・解答の転載の権利 | 本文・画像・正答は DB のみ（本人のみ RLS）。解説は転記しない |
| 社労士・土木への影響 | 新規テーブル・新規接頭辞・`AnyItemSolver` の1行のみ。既存の集計は `exam_id` で分離済み |

## 9. 決めたこと（異論があればここを直す）

1. 解答は**全設問を画面入力＋自動採点**。紙・手書きは前提にしない。
2. 問題は**全大問を文字**で取り込む（当初は第3〜5問を画像にする案だったが、字形の復元で文字にできた。画像は DB に入れにくい）。
3. 解説は転記しない（正答のみ）。
4. FSRS のカードは1回12枚（仕訳1組・金額1問・第3問・第4問・精算表）、6回で72枚。
5. 取り込みの順序は第39回（最新）→ 第38〜34回。
6. 第3・4問の**採点対象外の「計算で求める数値」**は採点前は隠す（見せるとヒントになるため）。判定は `build_cards.py` の `hint_words`:
   - 部門費振替表: 表の最初の金額の行（問題に与えられた「工事直接費」などの行）は残し、それより下の金額を隠す。1桁ずつの枠の金額（第34回）も同じ。
     **ただし資料に「?」がある回（第34・39回の第4問 問2）は隠さない**。解答用紙に印字された数値（与件）から配賦率などを逆算させる問題で、隠すと解けない（2026-11-13 の精査で判明し、DB の `frame.hide` を外した）。
   - 工事別原価計算表・工事原価明細表: **問題文に出てこない数値**を隠す（与件は問題文の資料にあるため）。
   - T勘定（第34・37回の第3問）: 隠さない。勘定口座の数値は解答用紙に与件として印字されているため（問題文の資料には元帳の要素しかない）。
   第34〜39回の全表で、隠れる語と残る語を目視で確認した。

### 本番形式模試（K6）の補足

- 受験状態は `denken_mock_sessions` の1行。`answers` は `MockAnswers`（問ID → 解答・仕訳・メモ）、`score` は素点（/100）、`section_scores` は大問ごとの得点。
- `subject_id='kk2'` は App 側の科目絞り込みに一致しないため、他の模試の集計に混ざらない。
- 残り時間はタブが見えている間だけ減る。0 になると自動で終了・採点する。
- 正解扱いの基準は復習カードと同じ（仕訳・金額は満点、第3〜5問は得点率80%以上）。未解答は誤答扱い。
- 合格基準70点・試験時間90分は公式で未確認（画面にも注記）。配点は資格スクール大栄の予想。
