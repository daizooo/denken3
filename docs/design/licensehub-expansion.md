## 1. 目的

2027年8月の第59回社会保険労務士試験（日程は未発表、8/22(日)と推定）に向け、既存アプリを**社労士の演習・記録の唯一の場所**にする。

- 問題は**テキスト**で持つ。会社PC（ブラウザ・周囲の目がある環境）で、問題文と選択肢だけをコピーして解ける。
- 解答は**○/×（または選択肢）で記録**し、正誤をアプリが採点して、理解度（A/B/C）とFSRSの復習予定に反映する。
- 電験の既存データ・機能は**一切壊さない**（`exam_id='denken3'` のまま共存）。
- アプリ名を資格に依存しない「LicenseHub」にする（§11。表示名は1か所の定数に集約し、後から変更できる）。

### 非目標

- 電験の機能変更（本設計は追加のみ）。
- 講義動画・教科書本文の取り込み（教科書はトリセツの紙。アプリには入れない）。
- 複数ユーザー化（個人利用・RLSで本人のみ、現行どおり）。
- `denken_*` テーブル名・`exam_id='denken3'` の改名（互換のため据え置き）。

## 4. 設計方針とデータモデル

### 4.1 方針（`CLAUDE.md` 準拠）

- 新規ファイル中心。既存の大きなファイル（`App.tsx` 約1,330行）への追記は最小行数、末尾追加、trailing comma。
- マイグレーションは追加のみ。番号は**コミット直前**に他PRと照合して採番（現在 020 まで）。
- **本番DBへのSQLは、削除系を除いて Claude Code が実行する**（利用者に SQL エディタでの実行を依頼しない）。
  - 対象: migration（ADD COLUMN・新規テーブル等の追加）、データの投入・更新（upsert・UPDATE）、読み出しの確認、データを消さないロールバック（状態を戻す UPDATE）。
  - 経路: Supabase MCP（DDL は `apply_migration`、それ以外は `execute_sql`）。migration はリポジトリのファイルと同じ内容を、同じ番号の名前で適用する。
  - 手順: ①ローカルの PostgreSQL で EXPLAIN と実行（2回流して冪等）を確かめる ②本番で読み出しのみの確認SQL（件数・一覧）→ 本体 → 結果を確かめる SELECT の順に流す ③実行したSQLの全文と件数を PR本文とチャットに報告する。
  - **削除系（DELETE・DROP・TRUNCATE、データが消えるロールバック）は利用者が実行する。** PR本文とチャットの報告に必ず全文を出力し（ファイル名や要約だけで済ませない）、ロールバック用のSQLも全文を併記する。
    - 対象は文の種類で決める。`DROP POLICY IF EXISTS`・`DROP TRIGGER IF EXISTS`・`DROP INDEX` など、**データが消えない DROP も含め、DELETE・DROP・TRUNCATE を1文でも含む SQL は Claude Code が実行しない**（migration の冪等化のための DROP も同じ。Supabase MCP では確認待ちになり通らない）。
    - その SQL は、Claude Code が別の書き方に書き換えて自分で流すのではなく、PR本文とチャットに全文を出力して利用者に実行を依頼する。削除系を含まない形で書けることもあるが、書き換えるかどうかは利用者が決める。
    - 削除系を含む migration は、削除系を含まない部分と分けて出力しない。1つの migration として全文を渡し、適用後に Claude Code が結果を確かめる SELECT を流す。
  - Supabase MCP に接続できないときは、理由を明記したうえで SQL をファイルで渡し、利用者に実行を依頼する。
- 問題本文は**リポジトリに置かない**（DBのみ）。リポジトリに置くのは、本文を含まない「マスター索引」（ID・論点名・重要度・年度など）だけ。理由: データ追加のたびにPR・デプロイが要らない、修正が単純なUPDATEで済む、バンドルが肥大しない。作業用ファイル（PDF・JSON・スクリーンショット）は `docs/question-text-ocr.md` と同様、**リポジトリ配下に保存せずコミットしない**。

## 5. 問題本文の取得とオフライン

- 本文（statement・stem・explanation）は DB から**必要な分だけ**取得する。
  - `useItemBodies(ids: string[])`（新規）: IndexedDBキャッシュ→不足分を `lic_items` から `in` 取得（200件単位）。
- `offlineStore.ts` に `bodies` ストアを追加（`DB_VERSION` を 2 へ。`onupgradeneeded` で追加のみ。既存ストア・DB名は不変）。
- 起動時プリフェッチ: 今日〜14日先の復習対象＋現在の学習科目の未着手の先頭200件。
- 本文が未取得・取得失敗のときは、その肢を出題しない（空の問題を出さない）。

## 6. 演習機能

### 6.1 肢モード（一問一答）— 新規 `src/features/license/ItemSolver.tsx`

1. 肢の本文を表示。選択は **○ / ×** と **確信 / 迷い**。
2. 「解答する」で確定（解答前コミット）。確定後は変更不可、誤タップのみ「修正」で取り消し。
3. 正誤を `truth` と照合して表示、解説を表示。
4. 理解度を自動記録（§6.2）。「分からない」ボタン（`gaveUp`）は C を記録。
5. 「テキストをコピー」ボタン（§6.3）。

### 6.2 自動採点と理解度の写像

| 結果 | 記録する理解度 | FSRS |
|---|---|---|
| 正解 かつ 確信 | A | Easy |
| 正解 かつ 迷い | B | Good |
| 不正解 / 降参 | C | Again |

- `Attempt` を拡張（既存フィールドは不変、追加はオプション）: `confidence?: 'sure'|'unsure'`、`correct?: boolean`（記録時点の正誤を残す。後で `truth` が変わっても履歴は動かない）。肢の `selected` は `[1]=○`、`[2]=×`。
- 純関数 `statusFromAttempt(correct, confidence, gaveUp)` を `src/lib/license/attempt.ts` に新設し、vitest でテストする。
- `truth` が null の肢はこのモードに出さない（問モードのみ）。

### 6.3 コピー運用（画面を見ながら解かない）

- **単体コピー**: 既存 `formatForClipboard` と同じく、問題文＋肢のあとに「あなたの答え：」、続いて**25行の空行**、その下に【正解】【解説】。
- **一括コピー**（新規 `BatchCopy`）: 今日の復習キューから N 肢（既定10、5〜30）を選び、番号付きの1つのテキストにする。**答え・解説は含めない**。
- **一括記録**（新規 `BatchGrade`）: 同じ N 肢を**番号だけ**の一覧で表示（問題文は折りたたみ）。各行は ○/× と 確信/迷い だけを入力。送信すると一括で採点・記録し、その後に解説を表示する。
  - 送信前は、どの肢の正答も画面に出さない。
  - 送信後の変更は §6.1 と同じく「修正」のみ。
- 一括コピーした肢の組は、`BatchGrade` に引き継ぐ（コピー時に組をセッションとして保持。ブラウザを閉じても `localStorage` で復元。復元できない場合は、再度同じ組を作る手順を案内）。
- すべての肢は `hasBody` を持つので、`studyPlaceOf` は社労士では常に「会社」を返す。

### 6.4 選択式（空欄補充）

- 1科目＝1問、空欄A〜Eに語群（20語程度）から選ぶ。**空欄が肢（カード）**。
- 肢モードの派生: 空欄ごとに語群の番号を選び、正誤を判定。確信/迷いは同じ。
- 語群と空欄の対応は `answer_spec.blanks/wordbank` に持つ。

## 7. 本番形式模試（新規 `src/features/license/TextPaperRunner.tsx`）

- 択一式: 70問（7科目×10）、210分。選択式: 8科目×5空欄、80分。`denken_mock_sessions` を使用（`exam_id='sharoushi'`、`subject_id='taku'｜'sentaku'`、`paper_id='r08'`、`mode='cbt'`）。
- 解答の入力: 各問の本文＋選択肢を表示し、ア〜オを選ぶ。自動保存（既存のautosave方式を踏襲）。
- 採点: `answer_spec` と照合し、科目別点数を `section_scores` に保存。結果画面に**科目別の得点と足切り判定**を表示（択一4点・選択式3点を下回る科目を警告）。
- 公式PDFの年度は、問題文全体を1ページに並べず、**1問ずつ**表示する（電験のCBTと同じ操作感）。
- 年度の選択: 問が揃っている年度（R6〜R8）は、電験の年度別と同じく**いつでも選べる**。どれをいつ解くかは事前に決めず、進捗を見て選ぶ。持つのは**最終期限**（設定値 `mock_deadline`。既定は模試ゲート 2027/5/31）だけで、画面に残り日数と未受験の年度×式を出す。

## 8. 本試験の位置づけ・模試の誤答の復習・進級判定（温存は廃止）

### 8.1 模試の誤答の復習

- 結果画面に、誤答した問（選択式は誤答した空欄）ごとに、各肢の本文・正誤（○×）・解説・自分の解答・正答を出す。解説は肢IDが同じ出る順の肢から来る（§4.2 の座標で同じ行にマージ）。取り込み前は「解説未取り込み」と出す。
- 採点確定時に、誤答した問の肢（択一は5肢すべて、選択式は誤答した空欄）を理解度 C で記録し、日々の復習キュー（FSRS）に入れる。出題は既存の規則に従う（索引に載り、`law_status='ok'` の肢から出る）。
- 結果画面の得点には「出る順で既習の肢を含む。初見の予測には公開模試を使う」と明記する。

### 8.2 進級判定（学習科目ごと。厳しめ。閾値は `SHAROUSHI_PROGRESSION` の1か所）

次をすべて満たしたら「次の科目へ進んでよい」とする。表示のみで、次の科目の演習は止めない。

| 条件 | 内容 |
|---|---|
| ① 1周完了 | 索引にあるその科目の肢を、すべて1回以上解いた |
| ② 確信正答率 | 直近の結果が A（正解×確信）の肢が **85%以上**（迷いの正解 B は数えない） |
| ③ 重要度Aの取りこぼしなし | 重要度Aの肢で、直近の結果が C の肢が0件 |
| ④ 定着 | ①〜③を、**7日以上空けた2回**（記録日の終わり時点）とも満たす。最新の記録日の時点で満たしていること |

- 不合格の科目は、直近の結果が C・B の肢を「弱点」として一覧にし、その場で順に解ける（記録は既存の経路）。

## 14. 書籍（一問一答）の取り込み（PR-J1/J2）

- 方式は電験と同じ: 利用者が電子書籍のページのスクリーンショットを渡す → Claude Code のセッションが読み取ってJSON化 → スクリプトで検証・保存（`docs/question-text-ocr.md` の2ステップを踏襲）。作業用のファイルはリポジトリ配下に保存せず、コミットしない。
- JSON例（1肢）:

```json
{ "source_ref": "R03-RK-05-C", "statement": "…", "truth": false,
  "explanation": "…", "topic": "…", "importance": "A" }
```

- **書籍の肢が、`lic_items` の正本になる**（公式PDFの取り込み前は、座標をキーにして新規に作成する）。後からPR-Dで公式PDFを取り込むときに、同じ座標の肢と突き合わせて、`origin_statement`・`truth`・正答の検証に使う。座標が合わない肢は警告を出して手動確認にする。
- 出題回数から論点ごとの頻度を集計し、書籍に重要度がない場合は A/B/C を算出して付ける。
- 取り込みの単位は**学習科目**（1冊を丸ごと待たず、労基・安衛だけでも取り込める）。取り込みのたびに件数（年度別・温存対象の件数を含む）を報告する。
- 発売日（§2）に合わせて、①→④の順に取り込む。

## 15. テスト・受け入れ基準

- vitest（純関数）: ID の生成とパース、`truth` の導出（各問型）、`statusFromAttempt`、`ScoringModel` の足切り判定、`formatForClipboard` の「正解が25行目より前に現れない」、進級判定（§8.2）、`APP_NAME` と静的ファイルの一致。
- 既存の電験の全テストが変更なしで通る。
- MVPの受け入れ:
  1. 資格切替で「社労士」を選ぶと、10科目のタブが出て、電験の記録は変わらない。
  2. 書籍①の労基・安衛の肢で ○/× と 確信/迷い を選び、正誤と解説が出て、A/B/C が記録され、翌日以降の復習予定が立つ。
  3. 「テキストをコピー」の出力に、答えが先頭付近に含まれない。
  4. 模試で誤答した問の肢が、解説つきで確認でき、復習キューに入る（§8.1）。
  5. オフラインで、取得済みの肢の復習と記録ができ、復帰後に送信される。
  6. 表示名が LicenseHub になり、既存のログイン・オフライン送信待ち・キャッシュが失われない。
  7. 一括コピーのテキストに答えが含まれず、`BatchGrade` で番号だけの入力により記録できる。
  8. フィクスチャの通し取り込み（§12.2の3）が成功し、削除スクリプトで元に戻せる。
  9. 設定画面で、本試験日・科目の重みと学習順・目標日の上書きを変更でき、目標日が再計算される。
  10. 公式PDF（D）: 検証ゲートを通った年度だけが保存され、通らなかった問は理由つきの一覧に出る。（温存は廃止。§8）
  11. 本番形式模試（H）: フィクスチャの一式で、制限時間つきの出題、科目別得点、足切り判定（択一4点・選択式3点）が出る。本物の年度は使わない。
  12. 法改正フラグ（K）: `unchecked`/`review` の肢が復習・集計に入らず、一覧で確認できる。
  13. 足切りダッシュボード（I）: データが無い・少ない科目は「データ不足」と推定値の明記つきで表示される。公開模試の得点を入力すると、ゲート判定に反映される。
