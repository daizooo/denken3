### 1.3 ページの構造（1見開き）

## 2. 読み取り方式（決定）

**画像を Claude Code が直接読んで書き起こす**（`docs/question-text-ocr.md` と同じ運用。有料のAPIキーは使わない）。

1. Drive MCP の `download_file_content`（base64）→ 結果ファイル → PNGにデコード → `Read` で視認。保存先はスクラッチパッド（リポジトリ外）。
2. Drive MCP の `read_file_content`（OCRテキスト）は**本採用しない**。理由（実測）:
   - 左右・問題と解説が入り混じって並ぶ（対応付けが不確実）。
   - ○×の印が `X : 006` / `x 005` / `O 007` のように崩れ、`O` と `0` も混ざる。
   - 肢ラベルのカタカナが `ア→7`、`イ→1`、`エ→I`、`オ→*` に化ける（出典の肢が決まらない）。
   - 使うのは「画像の読み取りと食い違っていないか」の補助照合だけ。
3. 並列化: 見開きを章・ページ範囲で分け、サブエージェントに割り当てる（1エージェント約25見開き）。各自が中間JSONを書く。
4. 画像・中間JSONは**リポジトリ外**。確定した肢だけを `ingest.mjs` 経由でDBへ入れる。

## 3. データ仕様

### 3.1 出典 → `source_ref` の変換

出典（例 `R元.4-A`）→ `{年度}-{採点科目}-{問2桁}-{肢}`（例 `R01-RK-04-A`）。

| 要素 | 規則 |
|---|---|
| 年度 | `H29`→`H29`、`H30`→`H30`、`R元`→`R01`、`R2`〜`R8`→`R02`〜`R08`。範囲は H29〜R08 のみ（外れたら要確認） |
| 採点科目 | 第1編・第2編 → `RK`、第3編 → `RS` |
| 問 | 出典のハイフン前の数字を2桁に。RK は1〜10、RS は1〜7（8〜10は書籍外。出たら要確認） |
| 肢 | 画像で読んだ表記を `label_raw` に、A〜E に正規化（ア→A, イ→B, ウ→C, エ→D, オ→E）。OCRの `7/1/I/*` は使わない |
| 学習科目 | 編で決める（第1編 `rouki` / 第2編 `anei` / 第3編 `rousai`）。**検算**: RK の問1〜7 は `rouki`、問8〜10 は `anei`。食い違いは要確認（既存DBも同じ分け方） |

### 3.2 中間JSON（作業用。1見開き=1配列要素ではなく、1肢=1オブジェクト）

`ingest.mjs` の入力（`schema.ts` の `TranscribedItem`）に、検証用の項目を足した形。検証用の項目は `ingest.mjs` に渡す前に取り除く
（`KNOWN_KEYS` 以外は「不明な項目」で失敗になるため）。

```json
{
  "source_ref": "R03-RK-05-C",
  "statement": "…",
  "truth": false,
  "explanation": "…",
  "topic": "01 総則・適用",
  "study_subject": "rouki",
  "_meta": { "book_no": 87, "page": 38, "image": "IMG_0034", "difficulty": "普通", "basis": "法15条1項、則5条1項", "hon_page": "30p", "confidence": "ok" }
}
```

| 項目 | 規則 |
|---|---|
| `statement` | 問題文を**そのまま**（要約・言い換えをしない）。表は行ごとの文字表記に直す（例: 曜日ごとの労働時間）。図が必須で文字にできない肢は出力せず `skipped` に入れる |
| `truth` | 画像の○×の印（左ページ右端）。○=true、×=false |
| `explanation` | 右ページの解説を**そのまま**。冒頭の根拠（条文・通達の括弧書き）を含める。「必修基本書 …p」の行は `_meta.hon_page` に分けて解説には入れない |
| `topic` | `{章番号2桁} {章名}`（科目ごとに章番号は01から。例 `01 総則・適用`）。目次番号を先頭に置くと索引が目次順に並ぶ（`license-ingest.md` §1）。**書籍側の章名を使う**（既存の「論点未設定」は上書き） |
| `importance` | **Phase 1 では付けない**（書籍に重要度が無い。難易度は別物）。全科目の取り込み後に出題回数から A/B/C を算出する（§14） |
| `_meta.difficulty` | 易/普通/難。**DBには入れない**（`lic_items` に列が無い）。必要になったら追加のmigration（既存列は変えない）で別途決める |
| `_meta.confidence` | `ok` / `check`（読み取りに自信が持てない）。`check` は §4 のレビューに回す |

### 3.3 DBへの反映（既存基盤のまま）

- `ingest.mjs` は `lic_items` を upsert、`lic_questions` は既存なら触らない（公式PDFの `stem`・`answer_spec` を守る）。新規の問は `source='ippon'`、`stem=null`。
- **R06〜R08 の既存肢への上書きは、突合を通ったものだけ**（§4.2）。`origin_statement` は上書きしない（既存の挙動）。
- 書き込みは Claude Code が Supabase MCP の `execute_sql` で行う（§4.1。削除系は使わない）。`.env` の service key が無い環境のため。
  実行したSQLの全文と件数をPR本文に報告する。

## 4. 品質ゲート

### 4.1 目録と網羅の検証（本文の取り込み前に作る）

1. **画像目録**: 全232枚の下部のページ番号を読み、見開きの連続性（2,3 → 4,5 → …）を確認。欠落があれば利用者に連絡する。
2. **通し番号の連続**: 編ごとに001から欠番なし（欠番＝見開きの欠落か読み落とし）。
3. **対照表の読み取り**（p.444〜451、約8見開き）: 想定する座標（年度×問×肢→掲載ページ）の一覧を作る。
   取り込んだ肢との差分と、**肢の掲載ページが対照表の頁と一致するか**で、読み落とし・出典の読み違いを検出する。
   書籍に載らない肢（正当な不掲載）は差分として列挙し、利用者が了承する。

#### Phase 0 の結果（実施済み）

- **画像目録**: 232枚すべての見開きを確認。p.2〜453 に欠けるページは無く、左右・連続性も問題なし（`IMG_0229` が無いのはページの欠落ではない）。
  前付6枚（IMG_0010〜0015）はページ番号なし。扉3枚（IMG_0093＝p.156/157、IMG_0136＝p.242/243、IMG_0215＝p.400/401）は前後からの推定（`confidence: low`）。
- **対照表**（p.444〜451）: 択一式 847行（労基安衛 494 + 労災 345 + 掲載なし8）を画像から読み取り。重複なし、ページはすべて科目・問の範囲と整合。
- **網羅の照合**: 編ごとの通し番号の最大値と、対照表の掲載肢数が**完全に一致**する。

  | 編 | 通し番号の最大 | 対照表の肢数 |
  |---|---|---|
  | 労基（rouki） | 344 | 344 |
  | 安衛（anei） | 150 | 150 |
  | 労災（rousai） | 345 | 345 |

  → **取り込み対象は 839肢で確定**（想定の最大850肢との差の11は下記）。
- **書籍に載らない座標（11）**:
  - 法改正等で問題不成立のため掲載なし（対照表に「－」）8肢: 労基安衛 **R08 問5 のA・B・D・E**、労災 **R05 問7 のA〜D**。
  - 出題自体が5肢に満たない問 2問: 労基安衛 **R06 問2（ア〜ウの3肢）**、労災 **R04 問7（ア〜エの4肢）**。
  - 既存DBにある R08 問5 の該当4肢は書籍の対象外で、そのまま据え置く（正誤は `derived` のまま）。
- 結果（本文を含まない）は `docs/book-ingest/ippon-1/` に置く: `manifest.json`（画像→ページ・節・章・通し番号の範囲）、`taiseki.json`（座標→掲載ページ）、`taiseki_sentaku.json`（選択式の頁表）。
  章名・章番号の一部は前後のページから推定した（manifest の `chapter`）。`topic` を確定させるときに目次と照合する。

### 4.2 肢ごとの検証

| 検査 | 内容 | 不一致のとき |
|---|---|---|
| 正誤の自己整合 | 解説に「本肢のとおりである」→ true を期待。それ以外 → false を期待 | `check` に回し、画像を再確認 |
| 数値の再読 | 日数・金額・割合・条番号を含む肢は、別エージェントが画像と照合 | 食い違いは画像を正とする |
| 既存DBとの突合（R06〜R08） | 座標が一致する既存肢と、本文の一致（正規化後）・正誤の一致を見る | **書籍版を正とする**（2027年版が最新で、既存の設計も書籍の肢の本文・正誤・解説を公式で上書きしない作り）。本文・正誤が食い違っても書籍版で更新し、公式の原文は `origin_statement` に残る。食い違いは件数だけ報告する。既存が `null` → 書籍で埋める |
| 検証（既存） | `validateTranscription`（座標・肢ID重複・学習科目の整合） | 失敗の肢は保存しない |
| 抜き取り | バッチごとに約10%を別エージェントが再読し、一致率を報告 | 一致率が低いバッチは全数を再読 |

#### Phase 1a（労基）の結果

- **書き起こし**: 77見開き・344肢（通し番号1〜344が連続、座標は対照表と過不足なく一致）。`--dry-run` は344/344が合格。
- **抜き取り検証**: H29〜R05 の36肢（数字を含む肢を優先）を別担当が画像と1文字ずつ照合し、**差は0件**。
- **既存DB（R06〜R08、99肢）との突合**:
  - 正誤: **食い違い0**。既存が `null` の15肢（R06 問5、R07 問1、R08 問2）は書籍の値で埋まる。
  - 本文: 67肢は正規化後に完全一致（数字まで一致しており、書き起こしの精度の裏付けになる）。残り32肢は書き起こしの誤りではなく**書籍側の編集**:
    「本条」を条文番号で明示する／問の共通のリード文を各肢に取り込んで単独で読める形にする／全角半角の違い／旧仮名「なつた」→「なった」。
    例: R08 問5 C は、公式の肢が計算式だけで、書籍が条件を補って単独で成立する問にしている。
  - 方針: 一問一答では書籍版のほうが読みやすいため、**32肢も書籍版で `statement` を更新**する。`origin_statement` は上書きされない（既存の挙動）。
    戻す場合は `update lic_items set statement = origin_statement where id in (…)`（データは消えない）。
- **書籍に載らない R08 問5 のA・B・D・E**（法改正で不成立）は取り込み対象外で、既存のまま。
- 原文の誤記・脱字（例: 「含ないものとする」「法5条」）は補正せず、そのまま転記している。
- 作業用の書き起こしJSON（本文を含む）はリポジトリに置かない。

## 4.4 R06〜R08（公式PDF由来）の扱いと、今後の取り込み方針

**R06〜R08 の行は残す**（書籍の肢と同じ座標で1行にマージされているため、残しても重複しない）。理由:

1. **模試が使う**: R06〜R08 の問には `stem`（リード文）と `answer_spec`（正答。`one`/`count` と向き）があり、本番形式模試の表示と採点（`textMock.ts`）はこれを使う。書籍の肢（`ippon`）には両方とも無い。消すと模試が成立しない。
2. **正答・座標の正本**: 書籍の○×を公式の正答と突き合わせる基準になる（労基では食い違い0）。
3. **公式の肢は単独では解けないことがある**（R08 問5 A・B・D・Eは、条件の無い計算式だけ）。日々の演習は書籍版（単独で成立する本文）、模試は公式の `stem` と `answer_spec` という使い分けになる。

**法改正の観点**:
- 書籍（2027/4/1までの施行法令に補正済み）を正とするため、本文・正誤・解説は書籍版になる。R06〜R08 労基の99肢で、書籍と公式の正誤の食い違いは0（法改正で答えが変わった肢は見つからなかった）。
- 模試の採点は `law_status` を使わない（`answer_spec` の正答で採点）。`excluded` にしても模試には影響せず、日々の演習・集計から外れるだけ。
- 書籍に載らない公式の肢は、書籍が「法改正等により問題不成立」と判断したもの。**R08 問5 の A・B・D・E（労基）は `excluded` にする**ことを提案する（条件の無い計算式で単独では解けず、出版社も掲載していない。模試の採点は `answer_spec` なので影響なし）。
- 2027年4月の公告後に法令基準日（`law_base_date`）を更新して再照合する。書籍の正誤表が出た場合は、書籍の肢を直す。公式の原文（`origin_statement`）が差分の起点になる。

**注意（取り込みの副作用）**: `ingest.mjs` は既存行の `law_status` を `ok`、`law_note` を null に書き換える。労基の R06〜R08 の99肢では `law_status` はもともと `ok` だったので判定は変わらないが、**2026-10-14 の判定メモ（`law_note`）が消えた**。判定は `docs/license-law-review-r0{6,7,8}.sql` に記録があり、追記のみ・冪等なので再実行で戻せる。
今後の科目では、既存行の `law_status` と `law_note` を保持するよう `ingest.mjs` を直す（既存の `review` / `excluded` を `ok` に戻さないため）。

**今後の取り込みの手順（トークン量を抑える）**: 書籍版をそのまま入れる。

| 手順 | 方針 |
|---|---|
| 書き起こし | 従来どおり（座標は対照表で期待値を渡す） |
| 自動の検査（ほぼ無料） | 座標・通し番号の網羅、○×と解説の整合、`--dry-run` |
| 既存DBとの突合 | 本文のハッシュと正誤だけをDB内で比べ、件数と正誤の食い違いだけを出す（本文の差分は読まない） |
| 独立した抜き取り検証 | 原則やらない。完全一致率（編集されていない肢）が95%未満、または○×の食い違いが出たときだけ |

Phase 1a の実績: 書き起こし約1.3Mトークン、独立検証（36肢）約0.4Mトークン。独立検証を省くと、安衛・労災の残り約495肢は約1.9Mトークンで済む見込み。

## 6. 前提・リスク

- 書籍の本文を DB に保存する点は §4.1 の方針どおり（リポジトリには本文を置かない）。奥付に「個人の学習目的で使用」とあるため、**利用者個人の学習用途に限る**。
- 2027年版は2026年10月30日発行。法改正の反映は出版社の補正に従う（`law_status='ok'`、§9）。
- 画像の読み取りは人手より速いが、数値・○×の読み違いはあり得る。§4.2 の多重チェックで抑えるが、ゼロにはならない。利用中に誤りに気づいたら `data-correction-workflow.md` の手順で直す。
- Drive 画像の取得は1枚ごとに約2.4MB（base64）の結果ファイルが出る。作業ディレクトリのディスク使用量に注意し、デコード後は不要なファイルを消す。
